# C30 规则数据集设计

## 目标

为求职面试和作品集中的混凝土质量 POC 制作一份可直接检查、导入和演示的 C30 Excel 数据集。数据只覆盖 C30 泵送混凝土，按已确认的五档现场规则生成，不包含 C35 的 42A 电流基准。

## 输出文件

生成一个 Excel 工作簿，包含三个工作表：

1. `C30批次数据`：300 条批次级样本，用于驾驶舱、SQLite 导入和离线评估。
2. `C30规则`：把五档电流、工作状态、坍落度、扩展度、倒置坍落度时间、判定和处置措施结构化。
3. `字段说明`：说明字段含义、单位、允许值和使用边界，便于面试官审阅。

工作簿放入仓库的 `data/` 目录。原始规则截图不进入公开仓库。

## 样本分布

300 条样本采用固定随机种子，确保每次生成结果一致：

| 工况 | 数量 | 比例 | 电流范围 |
|---|---:|---:|---:|
| 正常 | 180 | 60% | 55–60A |
| 偏干·轻微 | 45 | 15% | 60–70A |
| 偏干·严重 | 30 | 10% | 70–80A |
| 偏稀·轻微 | 30 | 10% | 45–55A |
| 偏稀·严重 | 15 | 5% | 40–50A |

该比例只用于形成接近生产流的演示分布，不作为真实工厂发生率或统计结论。为了避免边界样本同时命中两档，生成逻辑按“严重优先、视觉和三项检测结果联合判定”处理重叠电流区间。

## 批次字段

每条数据至少包含：

- `batch_id`：虚构、唯一、可排序的批次编号。
- `production_time`：连续生产时间戳。
- `strength_grade`：固定为 `C30`。
- `condition_code`：`NORMAL`、`DRY_MILD`、`DRY_SEVERE`、`WET_MILD` 或 `WET_SEVERE`。
- `mixing_current_a`：落在对应规则区间的实时搅拌代表电流。
- `visual_workability`：对应工况的脱敏工作状态描述。
- `slump_deviation_mm`：相对 180mm 基准的带方向偏差。
- `measured_slump_mm`：由 180mm 与偏差计算得到，并控制在对应工况范围内。
- `measured_spread_mm`：对应扩展度区间。
- `inverted_slump_time_s`：对应倒置坍落度时间区间。
- `field_judgement`：合格、轻微异常或不合格。
- `disposition_action`：对应规则中的处置措施。
- `retest_required`：是否要求处置后复测。
- `rule_check`：Excel 公式验证该行是否同时符合电流、坍落度、扩展度和时间约束。
- `data_source`：固定为简短机器标识 `RULE_DERIVED`，不在驾驶舱中展示成长篇说明。

数值在规则区间内加入小幅随机扰动并保留合理精度：电流 0.1A、坍落度和扩展度 1mm、倒置坍落度时间 0.1s。生成过程不加入足以改变工况标签的越界噪声。

## 与现有 POC 的衔接

- 演示范围统一为 C30，移除 C35/42A 对当前主流程的影响。
- 将模型电流基准从 42A 调整为 C30 正常区间中心值 57.5A。
- SQLite 种子数据从 Excel 的 `C30批次数据` 导入，保证 Excel、接口和页面使用同一批数据。
- `/api/current-stream` 可根据批次代表电流生成稳定、可复现的批内时序，但界面继续标明其为规则驱动的演示波形，不宣称已连接 PLC。
- 驾驶舱只展示 C30，并使用 Excel/SQLite 数据，不再混入 C35 规则。

## 校验与验收

1. 工作簿共 300 条数据，五类数量与设计一致，批次编号唯一。
2. 所有 `strength_grade` 均为 C30，所有 `rule_check` 均为通过。
3. 每类样本的电流、坍落度、扩展度和倒置坍落度时间都落在对应规则范围内。
4. Excel 三个工作表经过公式错误扫描和逐页视觉检查，无截断、乱码或空白默认页。
5. 导入 SQLite 后，接口返回的批次数量、各类分布和代表性样本与 Excel 一致。
6. 自动测试覆盖正常、轻微异常和不合格三种判定，以及 C30 电流基准变更。

## 不在本轮范围内

- 不接入真实 PLC、ERP/MES 或 RTSP 摄像头。
- 不使用或复原受保密协议保护的真实批次记录。
- 不把规则生成数据描述为真实历史产线数据。
- 不扩展 C35 或其他强度等级。
